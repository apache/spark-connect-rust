# PySpark 4.3.0 module audit (the `pyspark-client` packages)

The class diff (`4.3.0-introspection-diff.md`) covers the connect classes. This audit covers
the modules and module-level names of the `pyspark-client` package: every module of the
packages of `connect_packages` (`python/packaging/client/setup.py` at `v4.3.0`), 352 modules.

Method: import each module from the v4.3.0 source with `pyspark.core` and `py4j` blocked (they
are not in `pyspark-client`, so `is_remote_only()` holds), and from this client. Then diff the
public names that the official module defines itself (functions and classes whose
`__module__` is the module), its submodules and its constants. Imported names (typing
aliases, re-exported helpers) are left out. 27 modules do not import in `pyspark-client`
either (`pyspark.mllib.*`, `pyspark.java_gateway`, `pyspark.shell`), and are left out.

## Gaps, and where they are closed

| Gap | JIRA |
|---|---|
| `pyspark.ml` (the DataFrame-based ML API) and the ML internals of `pyspark.ml.connect` (`io_utils`, ...), with the generated `pyspark.sql.connect.proto` | SPARK-61111 |
| `DataFrame.__arrow_c_stream__` and `pyspark.sql.interchange` | SPARK-61113 |
| `pyspark.util`: `fail_on_stopiteration`, `disable_gc`, `spark_connect_mode`, `default_api_mode`, `FuncT`, `__all__` | SPARK-61115 |
| `__all__` of `pyspark.sql.udf`, `udtf`, `avro`, `protobuf` | SPARK-61115 |
| the deprecated functions of `pyspark.sql.functions.builtin` and `pyspark.sql.connect.functions.builtin` (`countDistinct`, ...), which have no `__all__` | SPARK-61115 |
| `pyspark.sql.connect`: `functions.partitioning`, `avro.functions`, `protobuf.functions`, `table_arg`, `datasource`, `utils`, `logging`, `_typing` | SPARK-61115 |
| `pyspark.sql.connect.plan` `Read`/`Range`/`SQL` (placeholders), `Column.to_plan`, `pyspark.sql.connect.types` helpers, `pyspark.sql.connect.conversion` | SPARK-61116 |
| `SparkSession.Hook`: the hooks of `_registerHook` are not called | SPARK-61117 |
| `pyspark.pipelines`: `cli`, `init_cli`, `add_pipeline_analysis_context`, `block_session_mutations` | SPARK-61118 |

## Not gaps

- **Server-side modules**, which run on the server's Python worker (official PySpark there):
  - `pyspark.daemon`, `pyspark.worker`, `pyspark.worker_message`
  - `pyspark.sql.streaming.python_streaming_source_runner`, `pyspark.sql.streaming.proto.StateMessage_pb2`, `stateful_processor_api_client.SCALAR_TYPES`
  - `pyspark.sql.connect.streaming.worker.*`
- **RDD and classic internals**, of which a Connect client has no use:
  - modules: `pyspark.join`, `rddsampler`, `resultiterable`, `shuffle`, `statcounter`, and the RDD-based `pyspark.mllib`, most of which does not import in `pyspark-client` either
  - the py4j converters of `pyspark.sql.types` (`DateConverter`, `DatetimeConverter`, `DatetimeNTZConverter`, `DayTimeIntervalTypeConverter`, `NumpyArrayConverter`, `NumpyScalarConverter`, `TimeConverter`)
  - the classic dispatch helpers of `pyspark.sql.utils` (`dispatch_*_method`, `try_remote_*`, `to_java_array`, `to_scala_map`, `get_active_spark_context`, `ForeachBatchFunction`)
  - `pyspark.sql.group.dfapi` and `df_varargs_api`, `PandasGroupedOpsMixin`, `OptionUtils`, `JStreamingQueryListener`
  - `StreamingCheckpointManager`, which PySpark documents as supported in Spark Classic only
- **The gRPC client**, which the Rust transport replaces:
  - `pyspark.sql.connect.client.{core, artifact, reattach, retries}` and `pyspark.sql.connect.proto.base_pb2_grpc`
  - `convert_exception` and `convert_observation_errors` of `pyspark.errors.exceptions.connect`
  - the plan and expression classes of `pyspark.sql.connect.plan` and `pyspark.sql.connect.expressions`, which the Rust core builds (except those that SPARK-61111 and SPARK-61116 port), and `WindowFrame`, `StreamingQueryListenerBus`
- **Tools**, not part of the client API:
  - `pyspark.errors_doc_gen`, `pyspark.install`, `pyspark.threaddump`
  - `pyspark.sql.connect.local_server`, which the classic builder uses to start a local server
  - `pyspark.sql.transpile`, which the classic `UserDefinedFunction` uses
- **Types of the Rust core**: `DataTypeSingleton`, the metaclass of the singleton types of PySpark.
- **`pyspark.ml.connect`**: this client's is the native ML API of the Rust core (see `docs/compatibility.md`), not the deprecated torch-based one. So its models are `MLModel`, without `LogisticRegressionModel`, `MaxAbsScalerModel`, `StandardScalerModel` or `ArrayAssembler`.
- **Submodule attributes** that differ only because of import order (`pyspark.find_spark_home`, `pyspark.sql.conversion`, `pyspark.sql.streaming.state`, ...). The modules import.
