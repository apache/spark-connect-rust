## `SparkSession.Hook` (new in 4.3.0) — implemented

Nested `SparkSession.Hook` base class (`on_execute_plan`) + the `_registerHook` factory,
letting user code inject behavior around plan execution. In pyspark, `on_execute_plan`
rewrites the Python `ExecutePlanRequest` before the gRPC client sends it. This client uses
a native Rust transport that builds/sends the request in Rust — there is no Python request
to rewrite — so `Hook.on_execute_plan` is a passthrough and `_registerHook` is an accepted
chainable no-op, the same architectural rationale as the justified-absent
`SparkSession.client` / `Column.to_plan`. Both are present for API parity + subclassing.

## Signature notes (benign — ours accepts a superset of valid pyspark calls)

Fixed here: `SparkSession.Builder.appName/master/remote` param names now match pyspark
(`name`/`master`/`location`), and `remote` defaults to `sc://localhost`.

Remaining, intentionally benign: `Builder.config` accepts an extra optional `conf`;
`emptyDataFrame`, `DataFrameReader.text`, `freqItems`, `persist`, `replace`, `melt`,
`unpivot`, `nearestByJoin` use `None`-sentinel defaults (resolved to the documented value
internally) or default args where the reference marks them required — every valid
reference call is accepted.

## Full-surface sweep (beyond the 12 core classes)

A second pass diffed the authoritative public API (`__all__`) of `pyspark.sql.functions`,
`pyspark.sql`, `pyspark.sql.types`, `pyspark.sql.streaming`, plus datatype class constants
and `MergeIntoWriter`'s nested classes. It found — and this PR closed — real gaps the
class-only diff missed:

- `functions.__all__`: `variant_delete` (wrapper + dispatch arm), `PandasUDFType`,
  `ArrowUDFType`, `UserDefinedFunction`, `UserDefinedTableFunction`, `AnalyzeArgument`,
  `AnalyzeResult`, `SkipRestOfInputTableException`.
- `types.__all__`: `Geometry`, `GeometryType`, `Geography`, `GeographyType`, `VariantVal`.
- Datatype constants: `DayTimeIntervalType.{DAY,HOUR,MINUTE,SECOND}`,
  `YearMonthIntervalType.{YEAR,MONTH}`, `DateType.EPOCH_ORDINAL`, and the
  `Geometry/Geography/SpatialType` CRS/SRID/ALG constants (added as PyO3 `#[classattr]`s
  AND as native `apache-spark-connect` constants).
- `MergeIntoWriter.{WhenMatched,WhenNotMatched,WhenNotMatchedBySource}` nested classes.

After the fixes the `__all__` + constants sweep is fully clean (0 missing). The new
functions and constants exist on the native Rust side too (`spark_connect::functions::*`,
`spark_connect::{DayTimeIntervalType, GeometryType, ...}`).

Note: this is a NAME + SIGNATURE proof, not a behavior proof. Behavioral parity (the
official 4.3.0 connect test suite through our transport) runs on CI against the RC.
